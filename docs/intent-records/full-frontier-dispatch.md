title: Dispatch the entire independent useful work frontier
date: 2026/10/09
source: @ottojung
kind: constraint

An Antonina scheduling pass MUST delegate every independently useful, topologically ready workfront. One successful launch is not a stopping condition; continue dispatching until all other work is topologically blocked, duplicate, or has negative reconciliation value. This reinforces the topology-only admission intent. Never impose a worker count, project breadth barrier, or capacity/resource gate.

An open issue can already contain a delivered implementation or design awaiting review or merge. A successful terminal agent and an evidenced deliverable mean the original task is done even while the issue stays open. Do not restart that work just because its agent is no longer running. A revision, review, integration and independent follow-on task may be separately delegated if logically worthwhile. When uncertain, delegate bounded verification instead of performing deep archaeology yourself.

The scheduler must avoid repeatedly re-examining old terminal work while unstarted independent work is ready. Use compact live and terminal agent observations plus recent board comments, not scans of repositories, directories or lengthy issue histories. Deep verification is agent work.
